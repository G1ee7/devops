# CodeGuard

Учебный проект: **«CI/CD конвейерінде статикалық код талдауын автоматтандыру жүйесін әзірлеу»** — разработка системы автоматизации статического анализа кода в CI/CD.

## Текущий этап

Готов первый этап: адаптивный лендинг на казахском языке, созданный на HTML, CSS и JavaScript без сторонних зависимостей. Страница объясняет задачу проекта, будущий конвейер и назначение инструментов. Интерактивный пример показывает нарушение и исправление правила `eqeqeq`.

**Пример — локальная учебная симуляция.** Он не запускает ESLint, не обращается к GitHub и не показывает реальный результат CI. Лендинг опубликован в Cloudflare; настоящие проверки CI и автоматический деплой пока не настроены.

## Запуск

Требуется Node.js 22 или новее. Установка пакетов не нужна.

```sh
npm run dev
```

Открыть http://127.0.0.1:4173. Для другого порта задать переменную окружения `PORT`.

```sh
npm run build
```

Сборка копирует `public/` в `dist/`. Она не требует сети или внешних библиотек.

## Структура

- `public/index.html` — содержимое лендинга на казахском языке.
- `public/styles.css` — адаптивная верстка, стили и режим уменьшенной анимации.
- `public/app.js` — переключение примеров и демонстрация результатов проверки.
- `public/favicon.svg` — иконка сайта.
- `scripts/serve.mjs` — локальный сервер предварительного просмотра.
- `scripts/build.mjs` — подготовка статических файлов для публикации.

## Хостинг: Cloudflare

Сайт опубликован через **Cloudflare Workers Static Assets**:

**https://codeguard-devops.izanagitv86.workers.dev**

Worker: `codeguard-devops`. Настройки публикации находятся в `wrangler.jsonc`, статические файлы — в `dist/`. Pages и отдельный сервер не используются.

Для повторной публикации установить закреплённые в lock-файле зависимости:

```sh
npm ci
npm run deploy
```

Команда `deploy` сначала собирает сайт, затем запускает Wrangler. Требуется авторизация Cloudflare: API-токен в переменной окружения `CLOUDFLARE_API_TOKEN` и ID аккаунта в `CLOUDFLARE_ACCOUNT_ID`. Для Global API Key Wrangler использует `CLOUDFLARE_API_KEY` вместе с `CLOUDFLARE_EMAIL`. Не задавайте оба способа авторизации одновременно.

Ключи не сохраняются в репозитории. Для будущего CI используйте GitHub Actions Secrets и токен с правами, необходимыми для публикации этого проекта.

Первый деплой выполнен вручную. Автоматическая публикация после успешного анализа кода — следующий этап интеграции.

## Следующие этапы

1. Подключить ESLint, Stylelint и Semgrep с правилами для проекта.
2. Настроить GitHub Actions для push и pull request, сохранять отчёты анализа.
3. Настроить Cloudflare-деплой основной ветки только после успешных проверок.
4. Подготовить пример неуспешного и успешного запуска конвейера для защиты.

Концептуальная схема:

```text
GitHub push / pull request
          ↓
ESLint + Stylelint + Semgrep
          ↓
  Все проверки успешны?
  ├─ Нет → отчёт → исправление → повторная проверка
  └─ Да  → основная ветка → сборка → Cloudflare
```
